# AtTenTris plan, 2026-10-12

Approved: steps 1-3 and the data collection of step 4. Open: whether / how to fine-tune on round 4.
The GPU runs one job at a time (1 -> 2 -> 3); CPU play tests and round-4 collection for existing models
may overlap with GPU training. Quick tests: 64 games per setting; no depth-3 tests.

## 1. ToMe schedule screen (`tome_sched.sh`, ~2.5-3 h)
4-epoch screens from scratch, ToMe v4 recipe, 2 streams:
- A: 4 layers, fixed 0,0.17,0.17,0.17 (baseline)
- B: 6 layers, per-position budget 20 + max(0, (n0 - 36) / 4) blobs per stream, first merge 10%, then equal ratios
- C: 4 layers, the same budget
Measured: rule-token recovery (tome_iou.py, best IoU vs random merges), 64-game depth 1 / depth 2 APP,
depth-1 VS at 80/20 and 50/50. Deaths under garbage expected (no danger data).

## 2. ToMe v4.1 = the screen's winner (expected: B)
Pick by rule-token recovery first, then APP / VS; report before the full run. Train it 8 epochs (as
ToMe v4), then the DAgger 3 fine-tune (from the base, 70/30 with danger.npz, 3 epochs, lr 3e-4, 3 style
rows, as ToMe-dagger3). Tests: normal / danger / auto x no garbage / 80/20 / 50/50, 64 games; vs ToMe-dagger3.

## 3. Setup-token ablation (`setup_ablation.sh`, resumes at epoch 3 of 8; ~40 min)
v5.1 lineage with setup_* tokens dropped: base (8 ep) -> DAgger 2 ft -> DAgger 3 ft, same data / seeds /
schedules. Tests: base vs v5.1 (256 games, no garbage); final vs dagger3-ft (no garbage, 80/20, 50/50,
normal + danger); ms per move.

## 4. DAgger round 4: data collection and labelling only (~1 h CPU)
Students: AtTenTris dagger3-ft, nosetup-dagger3-ft, ToMe-dagger3, v4.1-dagger3, playing with the danger
tag at 80/20 and 50/50 on fresh seeds. Select trouble positions only (death / danger / holes rising /
unsure); label with CEM-survival (bot/results/survive/survive.txt) at beam 128, all moves, teacher
"danger" (same teacher, same tag). Report size + a takeover check.

## Data mix (for a later round-4 fine-tune, if approved)
The stored 1.09M set is never mixed into; each fine-tune draws its own mix per epoch. dagger3-ft per
epoch: original (1.09M + DAgger 1) 64%, DAgger 2 5%, danger 30%. Proposal for round 4: all danger data
(rounds 3 + 4, ~180k) as one 30% pool, original ~60%, DAgger 2 ~10%. Gates: val top-1 on the teacher's
positions and clean APP / TSD / quads within noise of dagger3-ft; raise the original's share if they slip.
